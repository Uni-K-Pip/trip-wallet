# 旅行支出管理 PWA 設計仕様

作成日: 2026-08-09

## 1. 目的

海外旅行中に外貨(初回は中国元)で使った金額をスマホから入力し、その日の為替レートで日本円換算して記録・集計する。上海旅行での利用を最初の対象とし、以降の旅行にも使い回せる構成にする。

## 2. スコープ

### 含むもの

- 旅行(Trip)単位でのデータ管理。旅行ごとに通貨を選択する
- 支出の記録: 日付・外貨金額・個別/共有タグ・カテゴリ・メモ・支払い方法・レシート写真
- その日の為替レートの自動取得と、支出ごとの手動上書き
- 円換算した合計・個別/共有別・カテゴリ別・日別の集計
- 旅行ごとの予算設定と残額表示
- 共有支出の人数割り表示(自分の負担額の目安)
- オフラインでの入力・閲覧
- JSON によるエクスポート/インポート

### 含まないもの

- 複数人でのデータ共有・同期。データは端末内にのみ保存する
- 「誰が払ったか」の記録と精算(誰が誰にいくら払うか)の計算
- サーバーサイド、アカウント登録、認証
- 銀行・カードとの連携、明細の自動取り込み

## 3. 技術構成

| 領域 | 選定 |
|---|---|
| ビルド | Vite |
| UI | React + TypeScript |
| 永続化 | IndexedDB(Dexie) |
| PWA | vite-plugin-pwa(Service Worker、manifest) |
| テスト | Vitest + fake-indexeddb |
| 配布 | GitHub Pages(Service Worker に HTTPS が必須のため) |

### ディレクトリ構成

```
src/
  domain/    純粋関数: 円換算・集計・カテゴリ定義
  data/      Dexie スキーマ + リポジトリ
  rates/     レート取得クライアント + キャッシュ + フォールバック
  ui/        React コンポーネント・画面
  app/       ルーティング・グローバル状態
```

計算ロジック(`domain`)を UI から切り離す。円換算と集計はもっとも誤りが許されない部分であり、ブラウザを起動せずテストできる状態に保つ。

## 4. データモデル

```ts
type Trip = {
  id: string;              // uuid
  name: string;            // "上海 2026-09"
  currency: string;        // ISO 4217。"CNY" / "KRW" など
  currencyDecimals: number;   // 最小単位の桁数。CNY: 2、KRW: 0
  startDate: string;       // "2026-09-12"
  endDate: string | null;
  budgetJpy: number | null;   // 予算(円)。未設定は null
  memberCount: number;        // 共有支出を割る人数。既定 1
  createdAt: number;
};

type Expense = {
  id: string;
  tripId: string;
  date: string;            // "2026-09-12"(現地日付)
  amountMinor: number;     // 外貨の最小単位を整数で保持(元 → 分)
  scope: 'personal' | 'shared';
  category: 'food' | 'transport' | 'sightseeing' | 'shopping' | 'lodging' | 'other';
  payment: 'cash' | 'mobile' | 'card';   // 現金 / Alipay・WeChat Pay / クレジットカード
  memo: string;
  rate: number;            // 記録時点の「1 外貨 = ? 円」を焼き付けたもの
  rateSource: 'api' | 'cache' | 'manual';
  photoId: string | null;
  createdAt: number;
  updatedAt: number;
};

type Photo = {
  id: string;
  blob: Blob;              // 圧縮済み JPEG
};

type RateCache = {
  key: string;             // "CNY:JPY:2026-09-12"
  rate: number;
  effectiveDate: string;   // API が実際に返した日付(土日祝は直近営業日)
  fetchedAt: number;
  source: 'frankfurter' | 'er-api';
};
```

### 設計判断

**レートは支出に焼き付ける。** 記録時のレートを `Expense.rate` に保存し、以降は再計算しない。API の値は後から改定されうるため、参照するたびに過去の記録の円換算が変わってしまうのを防ぐ。旅行の合計金額が見るたびに変動する家計簿は信用できない。

**金額は整数(最小単位)で保持する。** `12.34 元` は `1234` として保存する。浮動小数の丸め誤差を避けるため。円換算は表示時に `Math.round(amountMinor / 10 ** currencyDecimals * rate)` で求める。小数桁数を通貨ごとに持つのは、韓国ウォンのように最小単位が 1 の通貨があるため。円は整数に丸めて表示する。

**日付は端末のローカル日付を使う。** 現地時間に合わせた時差の補正は行わない。旅行中は端末の時計が現地時刻になっているため、これで現地日付と一致する。日付が意図とずれる場合は入力画面で手動変更できる。

**写真は別テーブルに置く。** 支出一覧の描画のたびに画像 Blob を読み込まないようにする。保存時は長辺 1280px へ縮小し、JPEG 品質 0.7 で圧縮する。

## 5. レート解決

### API

主: Frankfurter(ECB 参照レート、API キー不要、CORS 可、日付指定で過去日を取得可能)

```
GET https://api.frankfurter.dev/v1/{YYYY-MM-DD}?base=CNY&symbols=JPY
→ {"amount":1.0,"base":"CNY","date":"2026-08-07","rates":{"JPY":23.465}}
```

土日祝を指定すると直近営業日のレートが返り、`date` フィールドにその日付が入る。返ってきた `date` を `effectiveDate` として保存する。

副: open.er-api.com(API キー不要、当日レートのみ)

```
GET https://open.er-api.com/v6/latest/CNY  →  rates.JPY
```

### `resolveRate(currency, date)` の手順

1. `RateCache` に `{currency}:JPY:{date}` があればそれを返す(`source: 'cache'`)
2. なければ Frankfurter を呼ぶ。成功したらキャッシュに保存して返す(`source: 'api'`)
3. 失敗し、かつ `date` が今日なら open.er-api.com を試す
4. どちらも失敗したら、キャッシュ内でもっとも新しい日付のレートを返し、UI に「9/10 時点のレートを使用中」と明示する
5. キャッシュが空(初回からオフライン)の場合はレートを返さず、UI 側でレートの手動入力を必須にする

オンライン時はアプリ起動時に当日レートを先読みする。現地の電波状況や機内モードで入力が止まらないようにするため。

### 手動上書き

入力画面のレート行をタップして編集する。上書きした値はその支出の `rate` にのみ適用され(`rateSource: 'manual'`)、キャッシュは書き換えない。手動入力した値は同一旅行内の次回入力時の初期値として引き継ぐ。

## 6. 画面

### ホーム

上部にサマリーカード(合計 ¥/外貨、個別 ¥、共有 ¥、予算設定時は残額の帯グラフ)。その下に日付ごとにまとめた支出リストを表示する。各行はカテゴリアイコン・メモ・`120元 → ¥2,816`・個別/共有バッジ・写真サムネイル。右下に支出追加のフローティングボタン。

### 入力シート(ボトムシート)

使い勝手の核となる画面。

- 画面上部に金額を大きく表示し、外貨→円をリアルタイム換算
- **自前のテンキーを使う。** OS 標準キーボードは画面の約半分を占有し、下部のカテゴリ選択が見えなくなるため
- 個別/共有は 2 択の大きなセグメントコントロール
- カテゴリはアイコン 6 個のグリッド
- 支払い方法は 3 択のチップ
- メモは 1 行入力、写真はカメラ起動ボタン
- 日付は既定で今日。タップで変更可能
- レート行は「1元 = 23.47円(9/12 自動取得)」と表示。タップで手動編集

既定値のまま使える項目を多くし、金額・カテゴリ・保存の 3 タップで記録が完了する導線とする。

### 集計

- 個別/共有の内訳。共有には「共有合計 ¥30,000 / 自分の負担 ¥15,000(2人)」を併記
- カテゴリ別の横バー
- 日別推移

### 設定

- 旅行の作成・切り替え・編集(名前・通貨・期間・予算・人数)
- JSON エクスポート/インポート
- レートキャッシュの状態表示

エクスポートは全旅行・全支出を 1 つの JSON にまとめる(写真は base64 で含める)。インポートは**マージ方式**で、既存データは消さずに追加する。同じ id の旅行・支出が既にある場合はインポート側で上書きする。復元と、別端末からのデータ取り込みの両方を同じ操作でまかなうため。

## 7. エラー処理とデータ保全

| 事象 | 挙動 |
|---|---|
| レート取得失敗 | 5 章の手順でフォールバックし、使用中レートの日付を警告バナーに表示 |
| キャッシュも空 | レート手動入力を必須にして入力を継続させる |
| 写真の圧縮・保存失敗 | 写真なしで支出の保存を続行し、通知する。支出の記録を失わないことを優先 |
| IndexedDB 容量超過 | 写真を除いて再試行し、その旨を通知 |
| Service Worker 更新検知 | 「新しいバージョンがあります」トーストを表示し、タップでリロード |

### ストレージ永続化

iOS Safari はサイトが 7 日間使われないとストレージを削除することがある。ホーム画面に追加した PWA では緩和されるが保証はない。対策として:

- 初回起動時に `navigator.storage.persist()` で永続化を要求する
- 設定画面からいつでも JSON エクスポートできるようにする
- 旅行の終了日を過ぎたらエクスポートを促すバナーを表示する

## 8. テスト

### 自動テスト(Vitest)

- `domain`: 円換算(丸め・端数)、合計/個別/共有/カテゴリ別/日別の集計、予算残額、人数割り
- `rates`: 解決手順の全分岐(キャッシュ命中、Frankfurter 成功、Frankfurter 失敗→er-api、両方失敗→直近キャッシュ、キャッシュ空)を fetch モックで検証
- `data`: リポジトリの CRUD を fake-indexeddb で検証
- 画像圧縮: 縮小後の寸法とサイズ上限

### 手動確認チェックリスト

- iPhone / Android でホーム画面に追加し、アプリとして起動できる
- 機内モードで支出を入力・保存でき、直近レートの警告が出る
- 写真付きで保存し、再起動後も表示される
- JSON エクスポート → インポートでデータが復元される

## 9. 配布

GitHub Pages で公開する。開発中は `npm run dev -- --host` を使い、同一 LAN 上のスマホから実機確認する。
