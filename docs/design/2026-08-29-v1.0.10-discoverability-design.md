# v1.0.10 設計: 発見経路づくりと保守

2026-08-29 確定。

## 背景

v1.0.9(2026-08-27 公開)で収益化 Phase 2 が完了した。GoatCounter への計測が動き、起動数と寄付タップ数が貯まり始めている。

次の判断 — 起動数・`donate-click`・Ko-fi の入金実績を突き合わせて一手を決める — は数か月分のデータが要るので、2026-11〜12 頃になる。それまで着手すると決まっている実装は無い。

この空白期間に何をするかを決めたのが本設計である。`docs/design/2026-08-20-analytics-design.md` のリスク節に、あらかじめこう書いてある。

> 母数が小さすぎて判断できない可能性。数か月貯めても起動が数十回であれば、それ自体が「発見されていない」という答えになる。その場合の次の一手は収益化ではなく認知である。

**その「認知」を、答えが出るのを待たずに前倒しで始める。** ストアに並ばない以上、発見経路は検索と口コミしかない。11 月に読む数字そのものを増やす作業でもあるので、待ち時間と目的が噛み合う。

あわせて、リリース済みのアプリを腐らせないための保守と、記録に残り続けていた先送り 3 件の決着も行う。

## 作業範囲

| # | 作業 | 種別 |
|---|---|---|
| 1 | `description` / OGP / OG 画像 / 告知文 | 認知 |
| 2 | 先送り 3 件の決着 | 記録の整理 |
| 3 | 依存更新・翻訳の表記 | 保守 |

## 1. 発見経路づくり

### 現状の穴

`index.html` には `description` が無く、OGP も 1 つも無かった。この状態では、

- 検索結果の説明文が本文から機械的に抜き出される(アプリはほぼ空の SPA なので、まともな説明文にならない)
- SNS に URL を貼ってもカードが出ず、リンクがただの文字列になる

告知を始める前に、貼られた URL が意味を持つようにしておく必要がある。

### 文言の言語: 日英併記

`description` と OG 画像のタグラインは、日本語を先に、英語を後に並べる。

告知チャネル(note / X)が日本語アカウントなので流入の主は日本語圏になる。一方でアプリ自体は 4 言語・ECB 30 通貨に対応していて、中身は日本語圏に限定されない。片方に寄せるとどちらかの読者に対して不正確になるため、併記を選んだ。

`og:locale` は `ja_JP`、`og:locale:alternate` に `en_US` を置く。

### OG 画像

`public/og.png`(1200×630)を `npm run og` で生成する。`public/icon.svg` の `<g id="motif">` と `<defs>` を流用するので、アイコンとモチーフが必ず一致する(`scripts/generate-icons.mjs` が maskable を作るのと同じ手口。切り出しは `scripts/svg.mjs` の `extractGroup` を共用)。

**この画像を Service Worker の precache から外す**(`globIgnores: ['**/og.png']`)。250KB あるが読むのは SNS のクローラだけで、アプリの動作には使わない。precache に入れると全利用者が初回に 250KB を余分に落とすことになる。

SVG のテキストを sharp でラスタライズする際、`font-family` に総称名(`sans-serif`)だけを渡すと librsvg が等幅フォントに解決することがある。日本語が出る実在のフォント名(`Yu Gothic, Meiryo, Segoe UI`)を先頭に置く。

### 絶対 URL の配り方

`og:url` と `og:image` は相対パスを受け付けない。vite が既定で置換する `%BASE_URL%` は相対パスのままなので使えない。

`vite.config.ts` に `ORIGIN` を足し、`ORIGIN + BASE` を `%SITE_URL%` として `transformIndexHtml` で流し込む。公開先を変えるときに触る場所が `ORIGIN` と `BASE` の 2 つに収まる。

### html の lang

初期値を `en` から `ja` に変えた。`description` の先頭が日本語であることと揃える。

JS が起動した時点で `LangProvider` が表示言語(ja / en / ko / zh)に差し替えるので、これは JS を実行しないクローラ向けの初期値でしかない。

### 告知文

note 記事 1 本と X 投稿 5 パターンの下書きを作る。**リポジトリには入れない**(一度使えば終わる文章で、コードの正本ではないため)。

note 記事の主題は「アプリ紹介」と「ストア配布から降りた話」の 2 本立てにする。後者は個人開発者にとって実用的な情報(収益化した個人 Play アカウントは物理住所が公開される)で、検索流入が期待できるのはこちら側である。

**投稿は行わない。** 内容を確認したうえで、本人が投稿する。

## 2. 先送り 3 件の決着

v1.0.6(2026-08-12)の最終レビューで先送りにして以降、リポジトリの外の作業記録にだけ残っていた 3 件を、ここで閉じる。以後の根拠はこの節に置く。

### `money.ts` の `toFixed(4)` — 修正不要と結論

「1e21 以上で指数表記になりうる」という指摘だったが、実際に検証したところ **`toFixed` が `"1e+21"` を返しても `Number()` が同じ値に戻すので、丸め結果は文字列を経由しない場合と一致する**。値は壊れない。

コードは変えず、`src/domain/money.test.ts` に固定テストを 1 本足した。同じ指摘が再燃したらこのテストを根拠に却下する。

### `db.migration.test.ts` の `test.isolate` 依存 — 修正した

`afterEach` の `Dexie.delete` が、vitest の `test.isolate` 既定値 `true`(= ファイルごとに隔離され、`db.ts` のシングルトンが開かれない)に依存していた。このファイルにリポジトリ関数を使うテストを足すと、開きっぱなしのシングルトンが削除をブロックする。

`afterEach` で `db.close({ disableAutoOpen: false })` を呼んでから消すようにした。`disableAutoOpen: false` なので、次のテストが触った時点で開き直される。

**依存が切れたことを、リポジトリ関数(`listTrips`)を使うテストを 1 本足して確かめた。** 修正前にこのテストを書くと `DatabaseClosedError` で落ちる。

### `glob@11.1.0` の deprecated 警告 — 上流待ちで確定

`vite-plugin-pwa@1.3.0` → `workbox-build@7.4.1` → `glob@11.1.0` という transitive 依存。`vite-plugin-pwa` は最新版であり、こちらから消す手段がない。

`overrides` で握り潰すことはできるが、workbox のビルドが glob の API に依存している以上、上流が上げる前に差し替えるのは壊すリスクのほうが大きい。**警告として放置し、`vite-plugin-pwa` の更新時に再確認する。**

## 3. 保守

### 依存更新

8 パッケージをパッチ / マイナーで最新にした(`@testing-library/react` `@testing-library/user-event` `@types/react-dom` `@vitejs/plugin-react` `dexie` `sharp` `vite` `vitest`)。メジャーの更新は無い。`package.json` の範囲指定は `^` のままなので、変わったのは `package-lock.json` だけ。

### 翻訳の表記

ネイティブレビューは依然として受けていない。今回直したのは、言語の規則に照らして機械的に判定できる 2 点に限る。

- **韓国語の助詞**: `settings.confirmDelete` が `「${name}」과` と固定だった。`과 / 와` は直前の音節にパッチムがあるかで変わり、旅行名は動的なので固定できない。同ファイルの `deleted` が `을(를)` と併記しているのに合わせ、`과(와)` にした。
- **中国語のコロン**: `，` と `？` は全角なのに `:` だけ半角という不統一があった(3 箇所)。中国語の組版では `：` が正しいので揃えた。

どちらも `src/i18n/dictionaries.test.ts` に固定テストを足したので、以後は崩れない。

「鉤括弧「」は韓国語 UI では稀」「`새로 고침` は `새로고침` が一般的」といった様式の判断は、ネイティブでなければ決められないので手を付けていない。

## バージョン

`1.0.10` に上げる。利用者から見える変化は翻訳の表記だけで、機能追加は無いのでパッチとして切る。

## 検証

- `npm run test`(337 本)と `npm run build` / `npm run lint` を通す。
- ビルド後の `dist/index.html` で `%SITE_URL%` が絶対 URL に置換されていること、`dist/sw.js` の precache に `og.png` が入っていないことを確認する。
- ブラウザプレビューで `document.title` / `description` / `og:*` / `canonical` / `html lang` が意図どおりで、コンソールにエラーが出ないことを確認する。
- OG カードの実際の見え方は、公開後に X へ URL を貼って確かめる(README の手動確認チェックリストに追加した)。

## スコープ外

- **Ko-fi Membership、Web 決済での有料化。** 前提スペックの判断のまま保留(日本の特商法による住所表示義務)。
- **note / X への実際の投稿。** 下書きまで。
- **韓国語・中国語のネイティブレビュー。** 表記の統一とは別の作業として残る。
- **11 月の判断そのもの。** データが貯まってから行う。
- **ストア配布の再検討。** 恒久的に見送りの結論は変わらない。

## リスク

- **告知しても届かない可能性。** フォロワーの少ないアカウントからの発信なので、初速はほぼ出ないと見ておく。note の検索流入が効いてくるかどうかを数か月単位で見る。それでも動かなければ、11 月の判断は「収益化以前に発見されていない」という答えになる。
- **OG 画像の生成が開発機のフォントに依存する。** 生成物(PNG)を commit するので再現性は保たれるが、別の環境で `npm run og` を流すと字形が変わりうる。
- **`description` が併記のぶん長い。** 検索結果では途中で切れる。日本語を先に置いてあるので、日本語検索での見え方は保たれる。
