# v1.0.3 設計仕様

作成日: 2026-08-11

## 1. 目的

実際に使ってみて出てきた 4 つの改善を入れる。

1. 通貨の並び順を ISO 4217 コード順にする
2. 旅行名の入力例を `NY 2026-09` にする
3. ホーム/集計タブから旅行を切り替えられるようにする(ドラム式の選択メニュー)
4. 予算を個別と共有で別々に設定できるようにする

## 2. スコープ

### 含むもの

- `CURRENCIES` の並べ替えと、新規旅行の初期通貨の変更
- `TripForm` の placeholder 変更
- 旅行選択用のホイール部品と、ホーム/集計タブのヘッダーからの呼び出し
- `Trip.budgetJpy` の 2 分割、DB マイグレーション、バックアップ形式 v2
- 上記に伴うテストの追加・更新、README とバージョンの更新

### 含まないもの

- 対応通貨の追加(ECB 非対象通貨は従来どおり入れない)
- 集計タブへの予算表示の追加(現状どおり予算はホームにのみ出す)
- 旅行の並べ替え・お気に入り機能。ホイールの順序は既存の `listTrips()`(新しい順)に従う

## 3. 通貨の並び順

`src/domain/currency.ts` の `CURRENCIES` を ISO 4217 コードの昇順に並べ替える。

```
AUD 豪ドル / CNY 中国元 / EUR ユーロ / GBP 英ポンド / HKD 香港ドル
KRW 韓国ウォン / SGD シンガポールドル / THB タイバーツ / USD 米ドル
```

順序に依存しているのは `TripForm` の通貨セレクトだけなので、表示順以外への影響はない。`findCurrency` は線形探索なので順序を変えても結果は変わらない。

あわせて `TripForm` の新規作成時の初期通貨を `CNY` から `USD` にする。

`currency.test.ts` に「コードが昇順に並んでいること」を検証するテストを足す。将来通貨を追加したときに並びが崩れるのを防ぐため。

README の「対応通貨」の記述も同じ順に直す。

## 4. 旅行名の入力例

`src/ui/TripForm.tsx` の旅行名入力の placeholder を `上海 2026-09` から `NY 2026-09` に変える。

## 5. ホーム/集計タブの旅行選択

### 見せ方

ホーム/集計タブのヘッダーで、旅行名を `NY 2026-09 ▾` のボタンにする。タップすると既存の `Sheet` が開き、ドラム(ホイール)を回すか項目を直接タップして旅行を選び、「決定」で確定して閉じる。✕ や背景タップで閉じた場合は選択を捨て、元の旅行のままにする。

旅行が 1 件以下のときはボタンにせず、従来どおりただの見出しにする。切り替える先がないため。設定タブは既存の旅行リストがあるのでヘッダーを変えない。

### 部品の分割

- `src/ui/WheelPicker.tsx` — 汎用のホイール。`items: { id: string; label: string }[]`、`selectedId`、`onChange` を受け取る。旅行のことは知らない
- `src/ui/TripPickerSheet.tsx` — `Sheet` と `WheelPicker` を組み合わせた旅行選択シート。`trips`、`activeTripId`、`onSelect(id)`、`onClose()` を受け取る。DB にも `useActiveTrip` にも触らないので、単体でテストできる
- `App.tsx` はヘッダーのボタンとシートの開閉だけを持ち、確定時に `useActiveTrip` の `selectTrip(id)` を呼ぶ

スクロール位置と選択インデックスの変換は `WheelPicker.tsx` から export する純関数にする。

```ts
/** スクロール位置から選択インデックスを求める。範囲外は両端にクランプする */
export function indexFromScroll(scrollTop: number, itemHeight: number, count: number): number;
/** インデックスに対応するスクロール位置を返す */
export function offsetForIndex(index: number, itemHeight: number): number;
```

jsdom は実レイアウトを持たないため、この 2 つを分離しないとスクロール周りをテストできない。

### 動作の詳細

- 高さ 44px の項目を縦に並べ、`scroll-snap-type: y mandatory` でスナップさせる。リストの上下に (コンテナ高 - 44) / 2 のパディングを入れて、選択中の項目が中央のハイライト枠に来るようにする
- スクロール終了の検出は `scrollend` が Safari で使えないため、`scroll` イベント + 100ms のデバウンスで現在位置を拾う
- 項目をタップしたときは `offsetForIndex` の位置へスクロールして選択も更新する。実機でスナップが期待どおりに効かない場合でも操作が詰まないようにするため
- シートを開いた時点の選択位置へ初期スクロールする

### アクセシビリティ

- ホイールは `role="listbox"`、各項目は `role="option"` + `aria-selected` を持つボタン
- ヘッダーのボタンには `aria-haspopup="dialog"` を付ける

## 6. 予算の個別/共有分割

### データモデル

`Trip.budgetJpy` を廃止し、2 つのフィールドに置き換える。

```ts
type Trip = {
  // ...
  /** 個別支出の予算(円)。未設定は null */
  personalBudgetJpy: number | null;
  /** 共有支出のうち自分の負担分の予算(円)。未設定は null */
  sharedBudgetJpy: number | null;
};
```

共有予算は人数割りしたあとの「自分の負担分」に対する予算とする。個別予算と単位が揃うため、2 つを足せば「自分が使える額」になり、既存の「自分の負担合計」表示とも整合する。

### 移行

Dexie を version 2 に上げ、`upgrade` で旧 `budgetJpy` を `personalBudgetJpy` に移し、`sharedBudgetJpy` を null にして旧フィールドを消す。`budgetJpy` はインデックス対象ではないので `stores` の定義自体は変えない。

変換規則は純関数に切り出し、DB の upgrade とバックアップ取り込みの両方から呼ぶ。

```ts
/** v1 形式(budgetJpy を持つ)の旅行を v2 形式に直す。v2 形式ならそのまま返す */
export function migrateTripBudget(trip: Record<string, unknown>): Trip;
```

IndexedDB を経由せずに移行ロジックを検証できるようにするための分離。引数は `isTrip` の検証を通ったもの、または DB に入っている旅行レコードだけを想定する。予算以外のフィールドは触らない。

### バックアップ

- 書き出しは `version: 2` にする
- 取り込みは `version` 1 と 2 の両方を受け付ける。1 の旅行は `migrateTripBudget` を通してから保存する
- v2 のファイルを v1.0.2 以前のアプリで開くと従来どおり「対応していないバージョンです」で弾かれる。旧版を新形式に対応させることはできないため、これは受け入れる
- `isTrip` の検証は、`budgetJpy` / `personalBudgetJpy` / `sharedBudgetJpy` のいずれの形でも通るようにする(バージョン別に厳密化はしない。壊れた JSON を弾くのが目的で、型の網羅は移行関数側の責務)

### 集計

`TripSummary` の `budgetJpy` / `remainingJpy` を次に置き換える。

| フィールド | 突き合わせる支出 |
|---|---|
| `personalBudgetJpy` / `personalRemainingJpy` | `personalJpy` |
| `sharedBudgetJpy` / `sharedRemainingJpy` | `sharedPerPersonJpy` |

予算未設定なら予算・残額とも null。残額は負の値も許す(超過分が分かるようにするため。現状と同じ)。

### 画面

- `TripForm`: 予算欄を「個別予算(円)」「共有予算(円・自分の負担分)」の 2 つにする。どちらも空欄可。パース規則(NaN は null、負数は 0 に丸める)は現状の予算欄と同じ
- `HomeScreen`: 予算バーを個別・共有の 2 本にする。設定されている側だけ表示する。超過時に赤くなる挙動と、予算 0 のときは使用率 0 として扱う既存の規則は 2 本とも据え置き
- `SettingsScreen`: 旅行メタの `予算 ¥50,000` を `個別 ¥50,000 / 共有 ¥30,000` の形にする。設定されている側だけ出す
- `SummaryScreen`: 変更しない

## 9. 手動確認

実機で次を確認する。

- 旅行を新規作成すると通貨が ISO 順に並び、初期選択が米ドルになっている
- 旅行名の入力例が `NY 2026-09` になっている
- ホーム/集計のヘッダーをタップするとドラムが出て、回して決定すると旅行が切り替わる。✕ で閉じると切り替わらない
- 旅行が 1 件のときはヘッダーがタップできない
- 個別予算と共有予算を別々に設定でき、ホームにバーが 2 本出て、それぞれの残額が正しい
- v1.0.2 で書き出したバックアップを取り込むと、旧予算が個別予算に入る
