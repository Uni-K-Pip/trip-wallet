### C: `toHomeMinor` の丸めガード

`src/domain/money.ts` で、`parseMajorToMinor` は二進浮動小数の誤差(`1.005 * 100 = 100.4999…`)を `toFixed(4)` 経由で丸めてから `Math.round` しているのに、`toHomeMinor` は `Math.round` 直で非対称。

変更後:

```ts
export function toHomeMinor(
  amountMinor: number,
  decimals: number,
  rate: number,
  homeDecimals: number,
): number {
  return Math.round(Number((minorToMajor(amountMinor, decimals) * rate * 10 ** homeDecimals).toFixed(4)));
}
```

TDD で進める: 積が「〜.5 のわずか下」に落ちて `Math.round` 直だと切り捨てられる境界値を先にテストへ固定し(具体値は実装時に計算で確定する)、失敗を見てから修正する。既存テストが全部通ることで通常ケースの回帰なしも確認する。

### D: TripForm 換算先切替時の予算欄再フォーマット

現状、`src/ui/TripForm.tsx` の予算欄(personalBudget / sharedBudget、文字列 state)は初期表示時にだけ旅行の桁数でフォーマットされ、換算先セレクトを切り替えても桁が追随しない(例: EUR で「500.55」のまま JPY に切り替わる)。

仕様:

- 換算先セレクトの onChange で、両方の予算文字列を新通貨の桁数に再フォーマットする
- 数値として解釈できる非空文字列だけが対象。major の値を保ち、小数部の桁だけ合わせる
  - EUR「500.55」→ JPY 切替: 「501」(四捨五入)
  - JPY「50000」→ EUR 切替: 「50000.00」
- 空欄・数値として解釈できない文字列(「abc」等)は触らない
- 負値は符号を保ったまま桁だけ合わせる(保存時に `parseBudget` が 0 に丸める挙動は従来どおり)
- カンマは付けない(初期値と同じく `formatMajor(...).replace(/,/g, '')` の形)

実装イメージ:

```ts
/** 数値として読める入力だけ、新しい通貨の桁数に表示し直す。それ以外は触らない。 */
function reformatBudget(text: string, decimals: number): string {
  const trimmed = text.trim();
  if (trimmed === '' || !Number.isFinite(Number(trimmed))) return text;
  return formatMajor(parseMajorToMinor(trimmed, decimals), decimals).replace(/,/g, '');
}
```

注意: `parseMajorToMinor` は負値で `Math.round` を通すため、`formatMajor` の負号処理とあわせて「-500.55」→ JPY「-501」となり符号は保たれる。

TDD で進める: `TripForm.test.tsx` に「EUR の予算入力後に換算先を JPY へ切り替えると表示が丸まる」「JPY → EUR で小数 2 桁が付く」「空欄・非数値はそのまま」のテストを先に書く。

### F: 日付ラベルの言語別書式

現状 `src/domain/date.ts` の `formatDateLabel(isoDate, weekdays)` が全言語 `${m}/${d}(${w})` 固定で、en でも「9/12(Sat)」と出る。英語圏の慣習に合わせ、en のみ「Sat, 9/12」にする。ja / ko / zh は従来どおり。

設計:

1. 辞書(`Dictionary` = `typeof ja`)にトップレベルで `dateLabel: (m: number, d: number, w: string) => string` を追加する
   - ja / ko / zh: `` (m, d, w) => `${m}/${d}(${w})` ``
   - en: `` (m, d, w) => `${w}, ${m}/${d}` ``
2. `formatDateLabel` のシグネチャを変更する:

   ```ts
   type DateLabelDict = {
     weekdays: readonly string[];
     dateLabel: (m: number, d: number, w: string) => string;
   };
   export function formatDateLabel(isoDate: string, dict: DateLabelDict): string;
   ```

   `date.ts` は i18n を import しない(ドメイン層のまま、構造的型で受ける)。呼び出し側は `formatDateLabel(date, t)` と辞書ごと渡す。
3. 呼び出し箇所を追随させる(いずれも `t` を持っている):
   - `src/ui/DailyChart.tsx`(50・80 行付近)
   - `src/ui/ExpenseSheet.tsx`(131-132 行付近)
   - `src/ui/HomeScreen.tsx`(162 行付近)
   - `src/ui/SettingsScreen.tsx`(145-146 行付近)

シグネチャ変更なので、追随漏れは tsc がコンパイルエラーで捕まえる。

テスト:

- `date.test.ts`: 新シグネチャに追随し、ja 形式(`9/12(土)`)と en 形式(`Sat, 9/12`)の両方を検証
- `dictionaries.test.ts`: 4 言語すべてが `dateLabel` を持ち、en だけ曜日が先頭に来ることを検証

## リスク

- **CSS リネームの取り残し** → スタイルが静かに外れて見た目が崩れる。grep での全数確認と実機での見た目確認の二段構え。
- **`formatDateLabel` の追随漏れ** → 引数の型が変わるので tsc(`npm run lint`)がコンパイルエラーで捕まえる。
- **Actions メジャー更新の breaking change** → 実装時にリリースノートを確認。ワークフローは main への push / PR でしか走らない(feature ブランチの push 単体では動かない)ので、最終確認は main マージ後の実行になる。失敗したらワークフローだけ直して push すればよく、アプリ本体には影響しない。
- **`toHomeMinor` の丸め変更による既存表示の変化** → `toFixed(4)` が効くのは「ほぼ .5 ちょうど」の誤差ケースだけ。既存テスト全通過で通常ケースの回帰なしを確認。
- **DB 移行テストの DB 名衝突** → 各テスト後に `Dexie.delete('trip-wallet')` で確実に消す。既存の `repos.test.ts` 等と同一プロセスで走っても fake-indexeddb はテストファイル単位で独立している点は実装時に確認する。
