# v1.0.4 設計仕様

作成日: 2026-08-11

## 1. 目的

集計タブの 2 つの図を作り直す。

1. カテゴリ別・日別推移の図が分かりにくいので、分かりやすくする
2. 2 つの図を「個別 / 共有 / 自己負担」で切り替えられるようにする

現状はカテゴリ別も日別推移も同じ `.cat-row`(名前 + 横棒 + 金額)で描いていて、見た目が同じなので何の図か区別が付かない。カテゴリ別は棒が 1 位を基準にした長さなのに値は全体比の % を出していて、棒と数字が別の物差しになっている。日別は支出のあった日だけを並べるので、使わなかった日が詰まって消え「推移」が読めない。金額はどれも支払総額で、共有を人数で割った自分の負担では見られない。

## 2. スコープ

### 含むもの

- カテゴリ別を帯グラフ + 内訳リストにする
- 日別推移を縦棒グラフ + 平均線にする
- 合計カードの下に「個別 / 共有 / 自己負担」の切り替えを 1 つ置き、2 つの図に同時に効かせる
- 1 件あたりの自己負担を返す関数を足し、丸め方を全画面で揃える
- カテゴリごとの固定色
- 上記に伴うテストの追加・更新、README とバージョンの更新

### 含まないもの

- 合計カードの変更。切り替えの影響を受けず、常に旅行全体の数字を出す
- 集計タブへの予算表示の追加(予算はホームにのみ出す。v1.0.3 から据え置き)
- 切り替えの選択の永続化。セッション内だけ保持し、アプリを開き直すと「自己負担」に戻す
- 支払方法別・メンバー別といった新しい切り口の集計
- ホーム画面の変更。`summarize` の丸め方は変わるが、共有支出が 1 件のときは結果が変わらず、複数件でも差は数円に収まる

## 3. 画面

### 全体の並び

上から、合計カード → 切り替え → カテゴリ別 → 日別推移。切り替えは 1 つだけで、下の 2 つの図に同時に効く。図ごとに切り替えを置くと 2 つの図が別々のスコープを指せてしまい、並べて見る意味が薄れるため。

切り替えは既存の `.segment` / `.seg` / `.seg.active`(支出入力の個別/共有トグル)をそのまま使う。選択肢は「個別」「共有」「自己負担」の 3 つで、初期表示は「自己負担」。

各図の見出しの右に、いま何を見ているかを出す。合計カードの数字とは別物だと分かるようにするため。カテゴリ別は `カテゴリ別  自己負担 ¥83,600` のようにスコープ名と合計を並べ、日別推移は `日別推移  自己負担` とスコープ名だけにする(合計は同じ値なので 2 回は出さない。日別の数字は図の下の平均と最高で示す)。

### カテゴリ別

横 1 本の帯を構成比で区切り、その下に内訳リストを置く。

- 帯: 高さ 22px、両端を丸める。区画の幅は選択スコープ内での構成比。並びは金額の多い順
- 内訳リスト: 色の四角 + アイコン + カテゴリ名 + 金額 + 構成比(%)。行の並びは帯と同じ
- 支出 0 のカテゴリは帯にも凡例にも出さない

帯と凡例で同じ色を使うので、色が凡例の役割を果たす。

### 日別推移

縦棒グラフ。横軸が日付なので「推移」がそのまま読める。カテゴリ別の帯と見た目が完全に別物になる。

- 横軸の範囲: 最初の支出日〜最後の支出日。途中の支出がない日も 1 日ずつ埋める。旅行の `startDate`〜`endDate` は使わない(まだ来ていない日を並べても読めないため)
- 棒: 高さ 110px の枠内で `金額 / 最高額` の割合。上端だけ角を丸める
- 0 円の日: 棒の代わりに高さ 2px の灰色(`--surface-2`)の線を出す。日付は残す
- 最高額の日: 棒を明るい水色(`#7dd3fc`)にする。同額なら先の日
- 平均線: 桃色(`--accent` ではなく `#f472b6`)の破線を横に引き、右端に `平均 ¥11,900` と出す
- 日付ラベル: 棒の下に日と曜日を 2 行で出す。土曜は水色(`#7dd3fc`)、日曜は赤(`#fca5a5`)
- 図の下に `1日あたり平均 ¥11,900` と `最高 9/14 ¥21,500` を左右に出す

長い旅行でも横スクロールはさせず、画面幅に収める。

- 棒の間隔: 15 日以上なら 6px → 2px に詰める
- 日付ラベル: `step = Math.ceil(日数 / 7)` として `index % step === 0` の日だけ出す(7 日以内なら全部、14 日なら 1 日おき、30 日なら 5 日おき)

### 空のとき

2 種類を区別する。

| 状況 | 表示 |
|---|---|
| 旅行に支出が 1 件もない | `集計する支出がまだありません。`(現状のまま。切り替えも図も出さない) |
| 選択スコープに該当する支出がない | 図の代わりに `共有の支出はまだありません。`(スコープ名を含める) |

後者は「全部が個別の旅行で共有を選ぶ」など普通に起こる。合計カードと切り替えはそのまま出す。

## 4. データ計算層

### 表示スコープ

```ts
// src/domain/summary.ts
export type ViewScope = 'personal' | 'shared' | 'mine';
```

データとしての `Scope`('personal' | 'shared')とは別物なので型名を分ける。`mine` が自己負担。

### 1 件あたりの自己負担

```ts
export function myShareJpy(e: Expense, trip: Trip): number {
  const jpy = expenseJpy(e, trip);
  if (e.scope === 'personal') return jpy;
  return Math.round(jpy / Math.max(1, trip.memberCount));
}
```

いまの `summarize` は共有の合計を出してから人数で割って丸めている(`Math.round(sharedJpy / members)`)。一方、カテゴリ別・日別で自己負担を出すには行ごとに割って丸めてから積み上げるしかない。両方が混在すると、カテゴリ別の合計が合計カードの「自分の負担合計」と数円ずれる。ずれた数字が同じ画面に 2 つ並ぶのは今回直したい分かりにくさそのものなので、`myShareJpy` を単一の真実にする。

`summarize` の `sharedPerPersonJpy` と `myTotalJpy` もこの積み上げに変える。既存の「行ごとに丸めてから足す」方針(`summary.ts` のコメント、`summary.test.ts` の同名テスト)と揃う方向の変更。

### 集計関数

```ts
export function breakdownByCategory(expenses: Expense[], trip: Trip, view: ViewScope): CategoryBreakdown[]
export function dailySeries(expenses: Expense[], trip: Trip, view: ViewScope): DailySeries
```

`view` で対象と 1 件あたりの金額を決める。

| view | 対象 | 1 件の金額 |
|---|---|---|
| `personal` | `scope === 'personal'` のみ | `expenseJpy` |
| `shared` | `scope === 'shared'` のみ | `expenseJpy`(割らない支払総額) |
| `mine` | 全部 | `myShareJpy` |

`breakdownByCategory` と `totalsByDate` を呼んでいるのは `SummaryScreen` だけなので、引数を増やしても影響は集計画面に閉じる(`summarize` と `groupByDate` は `HomeScreen` も使うが、そちらの引数は変えない)。

### 日別の戻り値

```ts
export type DailyPoint = { date: string; jpy: number };
export type DailySeries = {
  /** 最初の支出日〜最後の支出日を 1 日ずつ。0 円の日も含む。日付の昇順 */
  points: DailyPoint[];
  totalJpy: number;
  /** 棒の高さの基準 */
  maxJpy: number;
  /** 最高額の日。同額なら先の日。points が空なら null */
  peakDate: string | null;
  /** totalJpy / points.length。0 円の日も分母に含む */
  averageJpy: number;
};
```

日付の連続生成には `src/domain/date.ts` に関数を足す。

```ts
/** from〜to を 1 日ずつ並べた ISO 日付の配列。from === to なら 1 件 */
export function eachDate(from: string, to: string): string[];
```

既存の `parseIsoDate` / `addDays` / `toIsoDate` を組み合わせる。

該当 0 件のときは `points: []` / `totalJpy: 0` / `maxJpy: 0` / `peakDate: null` / `averageJpy: 0` を返す。`maxJpy` が 0 のときは画面側で `Math.max(1, maxJpy)` を使って 0 除算を避ける。

`totalsByDate` は使い手がいなくなるので削除する。型 `DateTotal` も同様。

### カテゴリの色

`src/domain/categories.ts` の `CATEGORIES` に `color` を足し、`categoryColor(v: Category): string` を `categoryLabel` / `categoryIcon` と同じ形で足す。ラベル・アイコンと同じ場所に置けば、カテゴリを増やすときに 1 か所で済む。

| カテゴリ | 色 |
|---|---|
| 食事 | `#38bdf8`(水色) |
| 交通 | `#a78bfa`(紫) |
| 観光 | `#4ade80`(緑) |
| 買物 | `#fbbf24`(橙) |
| 宿泊 | `#f472b6`(桃) |
| その他 | `#64748b`(灰) |

## 5. 部品の分割

`SummaryScreen` に全部書くと合計カード + 切り替え + 2 つの図で 200 行を超える。図を切り出す。

| ファイル | 役割 | 受け取るもの |
|---|---|---|
| `src/ui/SummaryScreen.tsx` | データ取得、`view` の state、合計カード、切り替え、空状態の出し分け | `trip` |
| `src/ui/CategoryChart.tsx`(新規) | 帯グラフ + 内訳リスト | `CategoryBreakdown[]` |
| `src/ui/DailyChart.tsx`(新規) | 縦棒 + 平均線 + 日付軸 + 下の要約 | `DailySeries` |

図の 2 つは計算済みの結果だけを受け取る表示部品にする。`trip` も `expenses` も渡さない。Dexie もスコープ切り替えも知らずに済み、テストは配列を渡すだけで書ける。

切り替えは `<div className="segment">` + 3 つの `<button className="seg">` だけなので部品にせず `SummaryScreen` に直接書く(`ExpenseSheet` の個別/共有トグルと同じ形)。

### 読み上げとテスト用の目印

縦棒は見た目だけの要素なので、各棒に `aria-label="9/12(土) ¥2,816"` を付ける。読み上げに効くうえ、テストがこのラベル 1 つで日付と金額を両方確認できる。

`data-testid` は凡例の各行の `cat-row` を維持し、`day-row` は棒を指す `day-col` に変える。

## 8. 手動確認

実機で次を確認する。

- 集計タブを開くと「自己負担」が選ばれていて、カテゴリ別が帯 + 内訳、日別が縦棒になっている
- 「個別」「共有」を押すと 2 つの図が同時に切り替わり、見出しの右の金額も変わる
- 切り替えても合計カードの数字は変わらない
- カテゴリ別の内訳の金額を足すと、見出しの右の合計と一致する
- 支出のない日が 0 円の細い線で残り、日付が飛んでいない
- 平均線と「1日あたり平均」「最高」の数字が図と合っている
- 2 週間以上の旅行で日付ラベルが間引かれ、横スクロールが出ない
- 共有支出が 1 件もない旅行で「共有」を押すと案内が出る
- アプリを開き直すと「自己負担」に戻っている
